# UPSLink · 飞牛 UPS 联动

把飞牛 fnOS 接入局域网里已有的 NUT 网络 UPS 服务（群晖、绿联、Unraid 或任何兼容 NUT 的上游），断电时自动关机，并把 UPS 的状态、趋势与电池健康做成一页看得懂的界面。

**纯标准库、零第三方依赖、只读监控、默认不关机。** 一个 fpk 装完，从此不用为了 NUT 配置去改 `/etc/nut/*.conf`。

[![CI](https://github.com/cavemannb/fnos-upslink/actions/workflows/ci.yml/badge.svg)](https://github.com/cavemannb/fnos-upslink/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-2f6bff.svg)](LICENSE)

> A NUT (Network UPS Tools) client packaged as a fnOS application. Read-only monitoring, conservative auto-shutdown, 30-day trends, and battery replacement reminders. Python standard library only — no third-party packages, no Node.js runtime, no CDN.

## 它解决什么问题

飞牛自带的「系统设置 → UPS」只认**插在本机 USB 口**的 UPS。而多数家庭是这么接的：

```
UPS ──USB── 群晖（NUT Server，3493/TCP）
                │
             局域网
                │
        飞牛（需要当 NUT Client）
```

飞牛这一侧没有界面可填，只能手改配置：把 `/etc/nut/nut.conf` 改成 `MODE=netclient`、在 `upsmon.conf` 写 `MONITOR ups@群晖IP 1 monuser secret slave`、还要停掉本机的 `nut-server`（否则它会去抢 USB 设备）。系统大版本升级后，这些改动和 `/etc/sudoers.d` 下的授权都可能被覆盖，又得重新来一遍。

**这个应用把上述流程变成一次安装 + 一张表单**，并补上原界面没有的能力：趋势曲线、断电统计、电池更换提醒、升级后自检。

适合你，如果：

- UPS 接在另一台 NAS 或树莓派上，由它做 NUT 服务器；
- 想让飞牛断电后自动、体面地关机，而不是硬掉电；
- 想知道「这台 UPS 最近稳不稳、电池是不是该换了」。

不适合你，如果：UPS 就插在飞牛本机 USB 口上——那种情况用系统自带设置更直接。

## 界面导览

打开页面，从上到下依次是"现在安全吗 → 最近稳不稳 → 细节"。

| 区块 | 回答的问题 | 内容 |
|---|---|---|
| **状态总览卡** | 现在安全吗 | 状态词旁直接标输出电压（市电在线 230 V）；副行一行小字：附加状态中文 + 已稳定时长 + **上次断电**（时间与时长加粗突出，取全部历史，不随下方时间范围变化）；电量 / 续航 / 负载三个大数字三列均分——电量下标电池阶段（放电中 / 充电中 / 已充满），续航下标按真实放电折算的「实测 xx 分」，负载下标视在功率 / 额定容量；底部一行参数胶囊：关机策略（蓝色）、切换区间、蜂鸣、LB/FSD 保护，超载时追加红色标签 |
| **电池健康度** | 电池还行吗 | 标题行给出健康结论（状态胶囊：健康 / 接近更换 / 该更换 / 未知）与电池规格（类型 · 低压阈值 · 电压）；左栏三个容量证据：实测满电（历史断电反推）、新电基线、衰减幅度，附样本口径说明；右栏投运至今的寿命进度条（剩 60 天转黄、过期转红显示「已超期」），下接保养入口与容量标定 |
| **趋势图** | 最近稳不稳 | 电量与负载双线，断电区间标红；1 时 / 6 时 / 24 时 / 7 天切换；鼠标划过显示该时刻读数。图下方直接跟随断电统计（次数、累计时长、上次、最长一次），随所选时间范围联动 |
| **折叠区** | 排障与配置 | 设备与驱动（型号/固件/序列号）、全部 NUT 变量（一键复制）、关机策略、健康自检 |
| **事件流** | 发生过什么 | 时间线，可按断电 / 状态 / 操作 / 错误筛选；`OL`、`OB`、`LB` 等简写自动补中文注释 |

![电池到期提醒](docs/screenshot-battery-due.png)

**关于 UPS 原始状态码**：`OL CHRG` 这类返回值与「市电在线 · 充电中」是同一件事的两种说法，同时显示等于说两遍。所以主界面只给中文，原码收进状态词的悬停提示；排障时在折叠区「全部 NUT 变量」和事件流里仍能看到完整原码。

**界面风格**：整套界面共用一层设计 token——语义软色（强调 / 警示 / 危险 / 正常各一档浅底）、六档圆角、四级字号、三级数字字号、统一的卡片内边距与焦点环。亮色与暗色只维护一份 token 表，深色主题不重复写组件样式，所以两套主题永远一致。窄屏（手机、平板竖屏）自动从两列回落单列，三个核心数字改均分三列，不做横向滚动。

界面在亮色与暗色下都可用（跟随系统）。

## 功能详解

### 自动关机：三种触发，都默认克制

| 触发条件 | 说明 | 默认 |
|---|---|---|
| 断电持续 N 秒 | 转电池后计时，到点关机 | 300 秒 |
| `LB` 低电量 | UPS 自己判断电压已低，立即关机 | 开启 |
| `FSD` 强制关机 | 上游（如群晖）发出的关机广播 | 开启 |

**总开关默认关闭**——装完只监控、绝不关机，必须手动勾选才生效。

### 安全演练

输入"假设断电持续几分钟"，应用只走一遍策略计算并告诉你结果，**不会执行任何关机命令**。用来确认阈值和开关组合是否符合预期，再决定要不要开总开关。

### 趋势与统计

- **5 分钟一个采样点**，状态一变立即补点，并在变化前一瞬再补一个——画出来是台阶而不是斜坡，断电时刻精确到秒。
- 按天写入 `trend-YYYYMMDD.jsonl`（短键 JSON，30 天约 700 KB），启动时自动加载与清理过期文件，**重启不丢**。
- 查询超过 600 点自动分桶降采样；桶内只要出现过 `OB` 就整桶标红，断电区间不会被平均掉。
- 断电统计始终基于原始采样计算，不基于降采样数据（否则时长会被高估）。

### 电池更换提醒

针对「电池鼓包了 UPS 才报警」这个痛点，用四层信号提前发现：

| 层级 | 机制 | 提前量 |
|---|---|---|
| 投运倒计时 | 填一次更换日期，默认 24 个月周期；剩 60 天转黄、30 天转红 | 按周期，最稳定 |
| 实测容量 | 从历史断电反推满电可用时长，与首次基线比较；衰减 ≥15% 提醒、≥30% 判定需更换，负载变化自动归一化 | 中期，通常 3–6 个月 |
| 充电异常 | 连续 7 天充不到 100%，视为内阻上升 | 早期 |
| 自检记录 | 读取 UPS 上次自检日期，超过 90 天提示去做一次 | 间接 |

证据不足时显示"未知"，不猜、不误报。**电池健康只做提示，不参与任何关机判断。**

### 电池保养排期

铅酸电池没有记忆效应，「定期放空」只会加速硫化——所以 UPSLink 排的不是深度循环，而是两件真正有用的事：

| 项目 | 建议频率 | 做法 | 记录方式 |
|---|---|---|---|
| 短测（轻放） | 每 30 天 | 拔掉 UPS 市电，90 秒左右插回 | 插回后自动记录，无需确认 |
| 容量标定 | 每 6 个月 | 「电池保养 → 容量标定」，放电 8~12 分钟（按当前续航推荐） | 标定结束自动记录 |

- 任何 30 秒以上的放电都会自动计入短测记录——拔电瞬间卡片自动进入「放电中 · 短测」计时，恢复市电后自动记账并重新排期，全程不需要点任何按钮；放得太深（最低电量低于 40%）会单独警告一次。
- 保养面板列出最近几次放电记录（时间、时长、电量降幅），方便核对自动统计是否正常。
- 过了计划日期，电池卡片只写「已过计划日期 N 天」并给出做法，不提供「推迟」按钮——做没做由放电记录说话，没做就一直是这个状态。
- 记录存于 `maintenance.json`。
- 保养排期只做提醒，不参与任何关机判断。

### 容量标定

实测容量依赖「足够长的真实放电」，但日常短停电（几分钟）永远达不到 8 分钟的采样门槛，自动关机开着时更是在 5 分钟就把 NAS 关了。容量标定用一个受控窗口解决这个问题：

- 点「容量标定」后，断电关机阈值**临时**抬到约 20 分钟，换来一段 15 分钟的放电窗口；
- 配置文件全程不被改动，窗口结束自动回原值；进程重启即作废，不存在「阈值被留在 20 分钟」的残留；
- 标定期间 **LB / FSD 保护照常生效**，电量降到 50% 自动中止——真停电时该关还是关；
- 操作：点「电池保养 → 容量标定」，拔掉 UPS 市电，放电到建议时长（按当前续航推算 8~12 分钟，界面有进度与倒计时），插回即可；
- **插回宽限**：到点、撞到 50% 保护线或手动结束时如果还在放电，会先宽限 180 秒而不是立刻关机——宽限期在顶部横幅和电池卡片同时倒计时，插回市电即解除；
- 建议放电时长跟着续航走：固件报 20 分钟续航的小电池只会被建议放 8 分钟，避免照搬「12 分钟」直接撞到 50% 保护线。

### 升级后自检与一键修复

飞牛大版本升级后，第三方应用可能被停用、配置文件或 `/etc/sudoers.d` 被重写。打开页面会自动跑 8 项检查：

上游地址是否还在、数据目录可写、配置文件存在、上游 NUT 可达、能读到状态、**关机权限是否还在**、自动关机是否仍开启、电池周期。

任何一项标红时，页面上直接给出修复动作；**关机权限可以点按钮重建**（应用以 root 跑一条固定、不接受参数的修复脚本），不需要 SSH，也不需要卸载重装。

## 安全边界

这段比功能更重要，因为本应用拥有执行关机的权限。

| 条件 | 行为 |
|---|---|
| `OL DISCHRG`（在线但带放电标记） | **视为在线，绝不关机**（很多 UPS 会这么报，手写脚本容易误判） |
| 网络中断 / 上游离线 / 连不上 | **只记日志，绝不关机** |
| `OB` / `OB DISCHRG` | 达到设定秒数后关机 |
| `LB` / `FSD` | 勾选后才立即关机 |
| 自动关机总开关 | **默认关闭** |

其它约束：

- 对上游**只做只读查询**（`LIST VAR`），从不发送 `SET` / `INSTCMD` / `FSD`。
- 页面只允许**局域网私有地址**访问，不做公网暴露，也没有账号体系。
- 无遥测、无外连、无第三方库；除你配置的上游 NUT 地址外不发起任何网络请求。
- 关机权限通过一条最小 `sudoers` 规则授予（仅 `shutdown` / `poweroff` 与修复脚本），常驻服务进程本身降权运行，不是 root。

## 安装

### 方式一：应用包（推荐）

从 [Releases](../../releases/latest) 下载最新的 `upslink-<版本>.fpk`（仓库内 `dist/` 也有构建产物）：

> 应用中心 → 右下角「手动安装」→ 选择 fpk

版本号每天自动递增：只要当天代码有改动，09:00 会自动构建并发一个 Release；没改动的日子不发版。想尝鲜可以盯 [Releases](../../releases)，想稳妥就隔一段时间装一次最新版。

装完桌面出现「UPS 联动」。本应用**不需要 Node.js**，只依赖 fnOS 自带的 `python3`。

### 方式二：独立安装（不装 fpk）

不想用应用包、或应用中心拒装时：

```bash
git clone https://github.com/cavemannb/fnos-upslink.git
cd fnos-upslink
sudo bash install-standalone.sh          # 默认 8099 端口
# 打开 http://<飞牛IP>:8099
```

卸载：

```bash
sudo systemctl disable --now upslink
sudo rm -rf /opt/upslink /etc/systemd/system/upslink.service
```

## 五分钟上手

### 1. 上游（以群晖为例）

1. 控制面板 → 硬件和电源 → 不断电系统：确认 UPS 已识别，勾选「启用 UPS 支持」。
2. 同页勾选「**启用网络 UPS 服务器**」，在「允许的设备」里加入**飞牛固定 IP**（只接受单个 IP）。
3. 若启用了防火墙，放行 `3493/tcp`。

### 2. 本应用

展开「关机策略与配置」→ 填上游 IP、端口 `3493`、UPS 名称 `ups`（群晖默认）→ 保存。

### 3. 按顺序做三件事

1. **测试连接** —— 能读到型号与状态；
2. **安全演练** —— 确认策略判断符合预期（不会关机）；
3. **勾选「启用自动关机」** 并保存。

断电等待建议 **300 秒**，并把群晖那侧设成 **15 分钟**，保证飞牛先关完、群晖随后关。顺序反了飞牛会被硬切。

> 顺带确认：交换机和路由器也接在这台 UPS 上。否则真停电时网络先死，飞牛根本收不到上游的 `OB`——这是这类方案翻车最多的一处。

### 4. 电池（可选但建议）

在「电池」分组填一次**投运日期**（更换电池当天），倒计时与容量基线才会开始工作。实测容量需要一次超过 8 分钟、电量确实下降的真实断电才会出现；等不到就点「容量标定」造一个受控的放电窗口。日常保养（每 30 天一次 90 秒轻放）在「电池保养」里一键开始。

## 兼容性

| 项 | 说明 |
|---|---|
| 系统 | 飞牛 fnOS 0.9+（Debian 12 底层），x86_64 |
| 上游 | 任何 NUT server：群晖、绿联、Unraid、树莓派自建等 |
| 驱动 | `usbhid-ups`、`nutdrv_qx` 均可，只要上游能 `upsc` 出来 |
| 运行时 | 系统自带 `python3`，无第三方包 |
| 端口 | 8099 |

已知限制：

- **只打包了 x86_64**。ARM 机型需自行改 `manifest` 的 `platform` 后重新构建，未做真机验证。
- 部分 UPS 不上报 `input.voltage` / `ups.temperature`，界面会自动隐藏对应行，而不是显示空值。
- `battery.runtime` 由 UPS 固件估算，通常偏保守；想要更贴近实际的值看「实测满电」。
- 没有 Web 鉴权。请只在可信局域网内使用，**不要做端口映射到公网**。

## 常见问题

**Q：飞牛系统设置里的 UPS 页面一直显示「未连接」，是坏了吗？**
不是。那个页面只检测本机 USB 设备，本应用是网络客户端，两者互不影响。别去点它。

**Q：会不会误关机？**
三条硬约束：`OL DISCHRG` 视为在线；连接失败只记日志；总开关默认关闭。判定只认 `OB`/`LB`/`FSD` 与断电计时，不看续航估算值。

**Q：为什么不直接装 `nut-client` 包？**
fnOS 自带 NUT，装额外包可能版本冲突；本应用直接用明文协议读 `LIST VAR`，不需要客户端二进制，也不需要 `upsmon`。

**Q：趋势图刚装上为什么是空的？**
数据从装好那刻开始积累，5 分钟后出第一个点，24 小时后才是完整曲线。

**Q：升级会不会丢配置和趋势？**
不会。配置在 `@appdata` 下，趋势按天落盘；升级走「停旧 → 换文件 → 启新」，数据目录不重建。

**Q：能不能同时监控多台 UPS？**
当前版本是一对一（一个上游、一个 UPS 名称）。多台可装多实例，但目前没有做多实例 UI。

## 构建与测试

```bash
bash build-fpk.sh                            # 产物：dist/upslink-<version>.fpk
python3 tools/smoke_test.py                  # 冒烟测试（10 项，内置假 NUT 服务端）
python3 tools/test_battery.py                # 电池健康逻辑（8 组）
python3 tools/test_calib.py                  # 容量标定状态机（10 组）
python3 tools/test_maint.py                  # 保养排期与逾期判定（11 组）
python3 tools/gen_preview.py ok|due|calib|maint   # 生成界面预览，不连后端
```

`gen_preview.py` 的每个模式都会同时输出亮色页和 `demo_dark.html`（强制深色副本），改样式时不用切系统主题就能两套一起看。

需要 `python3`（>= 3.8）。`build-fpk.sh` 会自检三件容易踩坑的事：归档条目不能带 `./` 前缀、`checksum` 必须等于 `app.tgz` 的 MD5、顶层结构要与官方 `fnpack` 产物一致。CI 跑的是同一套检查（Python 3.11）。

### 自动发版

`.github/workflows/release.yml` 每天北京时间 09:00 跑一次：过去 24 小时若 `app/`、`tools/`、`manifest` 等代码路径有提交，就递增补丁号（`1.9.1` → `1.9.2`）、同步 `app/server.py` 的 `APP_VERSION`、在 `CHANGELOG.md` 顶部插入当天条目，构建 fpk 后创建对应 tag 的 Release。只改 README 或截图不会触发发版。

- 版本号回写由机器人提交（`chore(release): vX.Y.Z`），这类提交会被下一次检查排除，自己不会触发自己。
- 想立刻发一版：Actions → 每日发布 → Run workflow，勾上 `force`。
- 同一版本号已有 Release 时跳过，不会覆盖已发布的包。
- 自动发版后本地仓库会落后一个版本，`python3 tools/sync_version.py` 把远端版本号拉回来（否则下次本地构建出来的包版本号与远端不一致）。

## 反馈与贡献

- **遇到问题**：用[问题模板](../../issues/new/choose)提 issue，务必附上「全部 NUT 变量」与「健康自检」结果——这两项能覆盖八成排查。
- **想要功能**：先讲使用场景，再说想要什么。

- **原则**：默认值必须是「不关机」。任何把自动关机默认打开的改动都不会被合并。
